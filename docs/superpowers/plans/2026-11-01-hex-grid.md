# Hex grid and mixed-size token support implementation plan

> Execute inline using superpowers:executing-plans; use a fresh reviewer after implementation.

**Goal:** Read and execute GM-approved Size ½/1 NPC turns on Foundry's four offset hex layouts and existing equidistant squares, alongside Size ½/1 occupants.

**Architecture:** Keep the existing pure core's offset geometry. Add a thin geometry adapter using Foundry's public token occupancy, snapping and center APIs. Translate a token's current position by grid-center displacement, preserving small-token placement within its cell; validate every candidate against snapping and occupancy. Serialize pixel waypoints on the private board for execution rather than reconstructing hex positions from square-grid anchors.

**Tech stack:** Plain ES modules, Node built-ins, Foundry 13.351/Lancer 3.1.3. No new runtime dependencies.

**Spec:** Existing docs/design.md anti-goals, owner-selected REQ-1, and copied campaign observations recorded in the dashboard handoff.

## Constraints and decisions

- GM approval, turn reservation, fresh-state checks and execution-off defaults stay mandatory.
- Support actor sizes 0.5 and 1; Size ½ documents may be 0.5×0.5 or 1×1. Every token must occupy exactly one Foundry grid cell. Larger and irregular footprints remain refused.
- Preserve actual token centers for LOS/collision and subcell placement for waypoints. Never resize/re-snap campaign documents during planning.
- Use hex distance for engagement; use Foundry grid offset ranges for hex bounds. Scene edges, missing geometry, off-grid tokens and unknown collision remain conservative refusals.
- Elevation differences, regions, terrain artwork semantics, special attacks and large-token movement remain manual.
- Initial milestone is source and local validation. Previously authorized test-world workflow may be used for read-only geometry observation; deployment is a separate action to report explicitly.
- Repository has no pinned OKF bundle or registered roadmap. Update affected existing docs only; retain stale_after.

## Review focus

1. Odd/even row/column parity and negative offsets: compare pure neighbors/distances against actual Foundry grids.
2. Half-cell tokens and full-cell Size ½ tokens: occupancy and collision centers must match their documents.
3. Pixel-rounded hex waypoints and interleaved asynchronous updates: final position and stale-state checks must remain strict within Foundry's rounding tolerance.
4. Padded map edges and hex rows taller than pixel-size division suggests: no truncated reachable rows or out-of-scene paths.
5. Half-size target engagement and shared cells: ordinary enemy blocking remains conservative; size ordering controls engagement.
